# Bhatta web

The public app for Bhatta: kiln map, kiln records with in-browser chain verification, the inspection
queue, the ledger, and the method page. Vite, React 19, TypeScript (strict), React Router, MapLibre GL
with OpenFreeMap and EOX Sentinel-2 cloudless tiles, viem for chain reads and EIP-712 signing.

## Commands

```sh
npm install                 # dependencies are pinned to exact versions
npm run dev                 # http://localhost:5173, proxies /api to http://127.0.0.1:8787 (the FastAPI app)
npm run dev:fixture         # same, but every API call is answered from src/fixtures/ (no API needed)
npm run typecheck           # tsc --noEmit
npm run build               # typecheck + production build into dist/ (served by the API at /)
npm run build:fixture       # production build that uses the sample fixtures
npm run preview             # serve dist/ on http://localhost:4173 (also proxies /api)

npm run fixtures            # regenerate the sample fixtures and chip images
npm run icons               # render the PWA icons from public/icons/*.svg
node scripts/check-vectors.ts   # browser encoding vs data/merkle/test-vectors.json (must pass)
```

Screenshots of every route at 390x844 and 1440x900, in English and Urdu, light and dark:

```sh
npm run build:fixture && npx vite preview --port 4173 --host 127.0.0.1 &
node scripts/screenshots.mjs      # writes screenshots/, prints console errors and horizontal overflow
# CHROME_PATH=/path/to/chrome-headless-shell node scripts/screenshots.mjs   if Playwright's browser is missing
# ONLY=overview,map node scripts/screenshots.mjs                             for a subset
```

## 3D and interactive pieces

- **Kiln explainer** (`src/components/KilnExplainer.tsx`, scene in `src/kiln3d/scene.ts`): three.js 0.170.0,
  dynamically imported when the section nears the viewport (about 138 KB gzip, never in the first
  paint). Fire shows the straight air loop of an FCBK against the zigzag path of a Zigzag kiln; smoke
  for the Zigzag is scaled by the measured black carbon reduction from `/api/summary` `impact`, and
  drawn equal when that figure is missing. "See it at 10 m" morphs to a top-down orthographic view
  and box-averages the render down to Sentinel-2's 10 m grid at true scale. Device pixel ratio is
  capped at 1.5; the loop stops when off-screen or the tab is hidden; reduced motion gets static
  frames and a stepwise slider. Without WebGL, the stills in `public/explainer/` are shown; rebuild
  them with `node scripts/make-explainer-stills.mjs` (needs the fixture preview and SwiftShader).
- **3D map**: the "3D" toggle pitches the map and draws extruded columns, height from p(FCBK)
  (read from the inspection queue). "Tour" flies through the districts to the densest FCBK cluster;
  any touch, wheel, key or Escape stops it; it is disabled under reduced motion.
- **Merkle proof path**: Verify on chain draws the proof bottom-up and folds it level by level.
- `node scripts/screenshots-3d.mjs` captures these states at 390 and 1440 (headless Chromium needs
  `--use-angle=swiftshader`, which the script passes).

## Sample data

`VITE_FIXTURE=1` serves fixtures generated by `scripts/make-fixtures.mjs`. Everything in them is
synthetic (kilns, probabilities, scene ids prefixed `SAMPLE-`, transactions, model hashes, impact
sources), and the UI shows a "Sample data" banner and per-number tags whenever it is on. The Merkle
tree, leaves, proofs and evidence hashes in the fixtures are real computations over the generated chip
images, built with `@openzeppelin/merkle-tree`, so "Verify on chain" genuinely checks them against the
sample root. With no contract in sample mode, the root is read from the sample ledger and the page says
so.

## How the pieces map to the code

| Route | File | Reads |
|---|---|---|
| `/` | `src/pages/Overview.tsx` | `/api/summary`, `/api/kilns` |
| `/map` | `src/pages/MapPage.tsx` | `/api/kilns`, `/api/kilns/{id}` |
| `/kiln/:id` | `src/pages/Kiln.tsx` | `/api/kilns/{id}`, `/api/chips/*`, `/api/ledger`, contract over RPC |
| `/kiln/:id/certificate` | `src/pages/Certificate.tsx` | same, plus `certified()` and `certificateHash()` |
| `/inspect` | `src/pages/Inspect.tsx` | `/api/inspect/queue` |
| `/ledger` | `src/pages/Ledger.tsx` | `/api/ledger` |
| `/method` | `src/pages/Method.tsx` | `/api/results`, `/api/audit`, `/api/summary` |

- `src/api.ts` is the only place that talks to the API. It normalises every response, so the pages
  work with the field names the API uses today (`counts_by_status`, `survey_count`, `priority`,
  `p_fcbk`, `FindingAttested`, a `scenes` object) as well as the ones in `docs/PRODUCT.md`.
- `src/lib/encoding.ts` is the browser copy of `contracts/scripts/lib/encoding.ts` (leaf, evidence
  canonical JSON with Python-exact probability rounding, kilnId). `scripts/check-vectors.ts` keeps it
  honest against the cross-language vectors.
- `src/abi/KilnLedger.json` is the real ABI copied from `data/abi/KilnLedger.json`. If `/api/ledger`
  returns an `abi` field, that wins.
- Inspector findings are signed as EIP-712 `Finding` (or `Revision`) under the domain
  `{name: "Bhatta KilnLedger", version: "1", chainId, verifyingContract}`, with `nonce = nonces(inspector)`.
  Without a wallet, "Use a demo key" signs with a throwaway key that has no inspector role, so the
  contract rejects it; the page explains that this rejection is the point.
- Strings live in `src/i18n/en.ts` and `src/i18n/ur.ts`. The Urdu has not been reviewed by a native
  reader and the app says so whenever Urdu is on.

## Notes

- No CSS framework. Tokens are in `src/styles/tokens.css` (light, dark via `prefers-color-scheme`, and
  a manual override through `data-theme`). Layout uses logical properties so Urdu (RTL) mirrors.
- `?lang=ur` and `?theme=dark` in any URL set the language and theme (used by the screenshot script).
- The service worker (`public/sw.js`) is registered only in production builds and never caches `/api`.
